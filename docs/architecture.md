# 基础功能开发契约 v1

配套的 [三人联调细则](integration.md) 补齐接口前置条件、控制器状态转换、BMP 字段判定和验收向量，必须一并阅读。

## 依赖方向

`ui → controller → bmp / stego → models / contracts / errors`

`stego` 可以调用 `bmp.iter_carrier_offsets`；`bmp` 不得反向依赖算法或界面。数据库不参与此链路。核心算法不创建窗口、不弹对话框、不写文件。

## BMP 解析边界（成员一）

第一版只接受 `BM`、40 字节 BITMAPINFOHEADER、`biPlanes=1`、`BI_RGB=0`、位深 8 或 24。其他 DIB 版本先明确拒绝，后续需要支持时共同扩展。宽为正数且是 4 的倍数，绝对高度 1～512，宽 1～512。高度为负表示 top-down。

- 使用小端解析文件头和信息头，以 `bfOffBits` 为像素起点，不硬编码 54。
- `row_stride = ((width * bit_count + 31) // 32) * 4`。
- 校验文件头、像素偏移、实际文件长度和像素区边界；禁止越界读取。`bfSize` 应与实际长度一致；BI_RGB 的 `biSizeImage` 可为 0 或实际像素区长度。
- 8 位图要求完整 256 项调色板（`biClrUsed` 为 0 或 256），逐项满足 `B=G=R=索引值`；不支持伪彩色或重排灰度调色板。否则修改索引最低位不能保证灰度仅变化 1。
- `BmpImage.raw_bytes` 保留整个文件。保存时保留头部、调色板、填充和尾部字节。建议写同目录临时文件后替换目标，失败清理临时文件。
- `iter_carrier_offsets` 按文件存储顺序遍历行；行内从左到右，24 位按 B、G、R，每通道取一位。忽略行填充；正负高度都使用文件顺序，保证读写一致。
- 预览另行按视觉方向逐行转成 RGB，输出 `P6\n宽 高\n255\n` 加 RGB 原始字节。Tkinter 仅用于显示，不代替 BMP 解析。

## 容量与数据帧（成员二）

每个有效像素字节贡献一个 LSB。载体位数：灰度 `W×H`，真彩 `W×H×3`。

`最大文本字节数 = max(0, floor(载体位数 / 8) - 13)`。

这是 UTF-8 **字节数**而非字符数。界面显示已用字节和最大字节。少于 104 个载体位时连帧头也无法保存，须拒绝嵌入，包括空文本。

| 字节偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII `LSB1` |
| 4 | 1 | 版本 1 |
| 5 | 4 | UTF-8 正文字节数，无符号小端 |
| 9 | 4 | 正文 CRC32，无符号小端 |
| 13 | N | UTF-8 正文，无终止符 |

整帧按字节顺序写入，每字节先 bit7 后 bit0。修改公式为 `(old & 0xFE) | bit`。只修改实际帧占用的位置，其余字节保持原样。返回通过 `dataclasses.replace` 构建的新 BmpImage。

提取先读 104 位，检查标记、版本和长度，再读取正文，验证 `zlib.crc32`，最后严格 UTF-8 解码。任一步失败抛 `InvalidPayloadError`。CRC 用于检测意外损坏，不是加密或身份认证。未来带密钥模式使用新版本或独立协议，不得偷偷改变 v1。

## API 与失败语义

函数签名和返回类型以 `lsb_lab/*.py` 为准。`load_bmp/save_bmp` 的系统 IO 错误保留为 `OSError`；格式损坏抛 `InvalidBmpError`，超出支持范围抛 `UnsupportedBmpError`，超容抛 `CapacityError`。

控制器未加载原图就嵌入、未生成载体就保存等状态错误抛 `LabError`。UI 捕获 `LabError` 和 `OSError` 显示清晰提示。所有失败操作保留之前成功的会话数据，不能先清空再尝试读取。输入或原图变化后需重新嵌入才能保存对应结果；未保存退出时提示用户。

## 小图教学验证的特殊说明

PDF 中的 4×2 灰度图只有 8 位，4×4 灰度图只有 16 位，无法容纳正式帧头。它们用于手动逐位验证 `?`、`?S` 的原始 LSB 操作，可在算法测试的内部辅助函数中实现，不作为正式应用载体；正式模式应明确报容量不足。不要为了通过小图示例取消长度字段或 CRC。

# 数据与可选数据库设计

## 基础阶段：无需数据库

本实验的核心输入输出是 BMP 和文本，不涉及账号、权限或并发业务。使用 `models.py` 中的数据类存放会话状态，使用 BMP 保存隐写结果。重新启动程序后通过读取 BMP 恢复隐藏信息，不依赖数据库，也不保存一份明文来伪装提取。

| 数据 | 位置 | 生命周期 |
| --- | --- | --- |
| 原始 BMP | 用户选择的文件，内存中为 BmpImage | 只读输入 |
| 隐写 BMP | 内存 stego，用户另存到文件 | 可长期保存 |
| 当前输入/提取文本 | SessionState | 当前会话 |
| 容量及帧元数据 | Capacity、13 字节帧头 | 即时计算/随载体保存 |
| 实验截图、结果表 | 建议 `output/` | 用于报告，默认不进版本库 |

## 可选：SQLite 实验记录

`schema.sql` 是后续记录噪声、JPEG、剪裁实验时的可选设计，当前没有初始化数据库，也没有实现持久化接口。无需为了基础功能先开发数据库服务。

- 一条 experiment 表示一次实验；多条 artifact 引用它的输入、输出、截图或提取文本文件。
- 不把 BMP 二进制或隐藏明文重复写进数据库。文件使用相对实验目录的路径及 SHA-256，便于验证材料是否改变。
- 时间统一存 UTC ISO 8601；展示时转本地时间。实验编号使用应用生成的 UUID 文本。
- 参数和指标使用 JSON 文本，例如噪声种子、噪声比例、正文长度、位错误率；应用应验证合法 JSON 和指标范围。
- `status` 区分未运行、成功和失败；失败记录不得被报告为提取成功。
- 启用外键；删除实验默认 RESTRICT，删除记录不自动删除磁盘文件。

未来接口可为 `create_experiment(...) -> str`、`add_artifact(...) -> int`、`finish_experiment(id, status, metrics, error) -> None`。等实际实验需求明确后实现，不在基础控制器中强制调用。

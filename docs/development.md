# 分工与验收

具体行为以 [三人联调细则](integration.md) 的状态表和测试基线为准。成员一同时维护共享测试夹具，成员二维护 contracts，成员三负责控制器状态测试和真实文件集成测试。

## 先统一，再并行

三人确认 Python 环境及 v1 契约。共享文件修改应先通知另两人；不要各自修改帧格式或像素遍历顺序。建议分支 `feat/bmp`、`feat/stego`、`feat/ui`，完成后通过代码评审合并到 `main`。远程仓库为 `git@github.com:LinSui-dev/information-security-tech.git`。

## 成员一：文件与像素

实现 `bmp.py` 的四个接口。自己构造小 BMP 字节作为测试输入，覆盖两类图、上下行方向、行顺序、非法签名、文件截断、伪彩色和超范围尺寸。读取后直接保存应逐字节相同。为另两人尽早提供小型灰度、真彩样例及预览数据。

## 成员二：算法

实现 `stego.py`，复用 contracts，避免重新定义格式。成员一未完成时可以用测试构造的 BmpImage 和临时测试桩提供位置，但生产实现必须调用约定的偏移迭代器。

验收：空文本、英文、中文和换行可往返；恰好容量可写，超一个字节拒绝；损坏 magic/长度/正文时明确失败；正文损坏触发 CRC；原图对象不变，头部、调色板和非占用字节不变。原始小图按 architecture 的教学模式说明处理。

## 成员三：界面与联调

实现 controller 和 Tkinter UI。界面有原图、载体图、容量、输入/提取文本，以及读取、嵌入、保存、提取操作。不要使用 Tkinter 直接打开 BMP 替代解析；使用成员一提供的 PPM 预览。

验收流程：打开两种原图 → 显示类型/尺寸/最大字节 → 输入中文 → 嵌入 → 另存 BMP → 关闭并重新打开磁盘文件 → 提取并比较原文本。另测取消文件选择、无原图嵌入、无载体保存、错误文件、容量不足和重复打开文件的状态清理。用真实磁盘往返，不能只测内存文本。

## 完成定义

- 三个模块实现且各自测试通过。
- 两类 BMP 的完整 UI 流程实际操作通过并截图。
- 提交运行说明、样例来源、测试命令及真实结果。
- 保存实验输入输出、设计决策和问题记录，后续用于报告。
- 本阶段不含噪声、JPEG、剪裁和带密钥扩展；后续四项仍属于课程必做内容。

## 当前验证范围

已提供共享数据结构、帧头与容量计算及其测试。当前骨架不提供可运行的 GUI 或已完成的隐写程序。`NotImplementedError` 是明确的开发边界，不属于业务异常，不应在 UI 中隐藏。
